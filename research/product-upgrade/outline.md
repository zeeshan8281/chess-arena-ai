# Evidence-mapped outline

AS_OF: 2026-10-13. Registry IDs fixed in registry.md. Two independent complete drafts follow this scope; recommendations are not shipped claims.

1. **Decision and product promise.** Build → fixed evaluation → inspect failures → revise harness → compare versions. Browser evidence [1–5], executable baseline precedent [11–13]. Medium confidence in fit; no demand validated. Counterclaim: this may overbuild a toy arena.
2. **What the user examples actually establish.** Immediate coding-agent onboarding [1]; persistent agent/version separation and diagnostic replay [2]; fixed-weight harness changes and isolated game state [3–4]; scenario-versus-full-game failures [5]. High confidence in visible documentation; low in transferred performance. Explicitly exclude inaccessible dataset/private anecdotes.
3. **A usable first contribution loop.** Starter contract, no-account first run where implemented, actual replay, export, clear next revision. [1–2,11–13]. Proposed, verified against app before copy claims. Scope excludes automatic training or uploaded-code execution.
4. **Minimum reproducible evaluation.** Public deterministic regression suite, explicit baseline/color/seed/limits, version manifest, observed outcomes and stopped categories. [4,6–7,9–10]. Distinguish public development suite from held-out evaluation. Counterclaim: fixed public tests invite overfitting; external hosted models need not be deterministic.
5. **Product and data design.** Run/version records; track separation; protocol cards; one population for denominators; failure-first inspector; actual replay and recoverable positions. [2,6–7,12–15]. Root source inspection only for feasibility. No fictitious Elo or uncomputed engine labels.
6. **Research agenda tied to harness edits.** Input/history, memory/context, parser/retry, budget and policies as separate controlled ablations. [3–7,9]. Do not infer internal reasoning or generalization from a few wins. Cases should diagnose observed failures, not become generic chess-puzzle expansion [14–16].
7. **Implementation sequencing and acceptance.** Small end-to-end slice first; source/config versions, paired seeded cases, machine-readable export, visitor progress. [1–2,11–13] plus stated recommendations. Functional checks before metrics/hosting growth.
8. **Counter-position, licensing and unresolved work.** Product dilution, contamination, small samples, unknown billing, untrusted code, author-reported results, outdated docs and inaccessible evidence. [4–5,7,9–10,15–16]. No security audit/user study/replication completed; browser observation is not execution.
